# @@title@@

A matching decompilation of @@title@@ (Game Boy Advance): `make` rebuilds `@@builtRom@@`, identical byte for byte to
the original ROM (SHA-1 `@@sha1@@`). The project was created by [romlift](https://github.com/macabeus/romlift)
@@romliftVersion@@.

## Setup

You need:

- GNU binutils for ARM (`arm-none-eabi-as`, `-ld`, `-objcopy`): `brew install arm-none-eabi-binutils` on macOS,
  `apt install binutils-arm-none-eabi` on Debian and Ubuntu;
- `make`, `git` and a C compiler (agbcc is built from source, and C files go through its preprocessor);
- Node.js 22.18 or later (npm runs romlift).

Then:

1. Put your own copy of the ROM at `@@romFile@@`. It is not in this repository and never will be.
2. Run `./setup.sh`. It checks the toolchain, fetches and builds agbcc into `tools/agbcc/bin`, installs romlift and
   generates the disassembly when `asm/` is absent. In a new `git worktree` it copies `@@romFile@@` from the main one.
3. Run `make`. It builds `@@builtRom@@` and ends with `@@builtRom@@: OK` when the SHA-1 matches `@@sha1File@@`.

The generated files are not in Git, so after a `git pull` or a checkout that changes `romlift.toml`, run `npx romlift
generate` (or `./setup.sh`) before `make`; until you do, `make` stops and says so. After one that changes the romlift
version `package.json` pins, run `./setup.sh` (it installs that version) and then `npx romlift generate` yourself:
`make` checks only `romlift.toml`, not which romlift generated the tree.

Until romlift is published to the npm registry (a pre-release limitation), the version `package.json` pins does not
resolve, so step 2 cannot install it. Set `ROMLIFT_CLI` to a romlift command you have, for example a built checkout
of romlift (`npm run build` there):

```sh
ROMLIFT_CLI="node /path/to/romlift/dist/cli/main.js" ./setup.sh
```

setup.sh then skips the npm install and runs that command to generate the tree; run the other romlift commands
through node the same way (`node /path/to/romlift/dist/cli/main.js generate` where this file says `npx romlift
generate`).

## Layout

| Path | What it is |
| --- | --- |
| `romlift.toml` | the project: modules, function names and boundaries, symbols |
| `src/<module>.c` | the C of each `c` module: `INCLUDE_ASM` lines until a function is decompiled |
| `asm/`, `data/` | the disassembly and the data, generated by `npx romlift generate` (not in Git: `./setup.sh` generates them) |
| `ldscript.txt`, `symbols.ld`, `modules.mk` | the link order, the RAM symbols and each C module's compiler, generated (not in Git) |
| `expected/`, `objdiff.json` | each module's objdiff target source (`make expected` assembles it into `build/expected/`) and objdiff's project file, generated (not in Git) |
| `include/` | `include_asm.h` (the `INCLUDE_ASM` macro) and `macros.inc` (the assembler macros) |
| `Makefile`, `mk/*.mk` | the build, and the recipe of each C compiler |
| `tools/agbcc` | the compiler, a submodule of [pret/agbcc](@@agbccUrl@@) |

Never edit the generated files: change `romlift.toml` and run `npx romlift generate`. Decompiled C goes in
`src/<module>.c` (or a `src/*.c` file it `#include`s); a `const` array in C needs its module's data range (`data_start`
in `romlift.toml`). `npx romlift rename <old> <new>` renames a function in `romlift.toml` and in the C together;
entries with `from = "sig:…"` were named by library signatures; code that runs from RAM is declared by hand as an
`[[overrides]]` entry with `runs_at`. To compare a function with the original in objdiff, run `make expected` and open
the project:
`objdiff.json` lists the C modules. `AGENTS.md` has the details.
