## Deviations from the roadmap

Phase 1 ran as nine components in three waves (roadmap, "As executed"); D54 records why. The
deviations from roadmap 1.0–1.D, in short: (a) 1.B moved into wave 0 as `p1-foundation`; (b)
`foundation/isa/types.ts` belongs to `p1-isa`; (c) the binutils runner and the corpus belong to
the ISA component, with the corpus core in `src`; (d) `doctor` moved to wave 2; (e) two gate
components, `p1-gates-early` (g1–g3) and `p1-gates-late` (g4–g6); (f) new files `src/api/files.ts`,
`src/foundation/util/prng.ts`, `test/helpers/architecture.ts`; (g) the CLI types were frozen in
wave 0; (h) `GateSpec.tier` accepts `'both'`; (i) the real tier runs before the ci tier; (j)
`npm run lint` is the architecture checker alone.

Found during integration and at the close:

- **Branch names.** The phase branch is `phase-1`, not the roadmap's `phase/1-decoder`, and the
  component branches are `phase-1-p1-<component>`. Once the phase branch was named `phase-1`, a
  component could not be `phase-1/p1-<component>` (a ref cannot be a file and a directory); the
  roadmap's own names, `phase/1-decoder` and `phase/1/p1-isa`, would not have collided. The flat names
  are now the documented practice (AGENTS.md, roadmap "How a phase runs", D55 j).
- **The exit commands grew.** The closing gate runs fourteen commands instead of the roadmap's ten:
  `bench poc-check`, `bench dataset-check`, `bench provenance` and `romlift doctor --json` with stdin
  closed are added, and `test:local` runs with `ROMLIFT_REQUIRE_LOCAL=1`, so a missing benchmark input
  fails instead of skipping. Each addition only makes the gate stricter.
- **Mutation-suite command.** `node --conditions=source --test test/mutation/phase1/` fails on
  Node 24.15 with `MODULE_NOT_FOUND`: the test runner treats a directory argument as a module to run.
  The working spelling is a glob, `node --conditions=source --test 'test/mutation/phase1/*.test.ts'`
  (what `npm test` already does); `npm run lint` runs the architecture mutation file. The same holds
  for the gates: `node --test test/gates/` fails, `'test/gates/*.test.ts'` loads all 68 gate files.
- **`printer.yml` is not measured yet.** The threshold "`printer.yml` passes on apt and Homebrew
  binutils" needs CI on the pushed branch. Two binutils versions were measured locally: Arm's
  ArmGNUToolchain 15.3.Rel1 bundle (2.45.1, the PATH default) and devkitARM's GNU Binutils 2.43.1
  (`/opt/devkitpro/devkitARM/bin`), both 100% on every section ("The corpus"). The 2.45.1 build is
  Arm's bundle, not Homebrew's `arm-none-eabi-binutils` formula that `printer.yml` installs (2.47);
  apt's 2.42 and Homebrew's 2.47 are what CI still has to measure.
- **Merge to `main`.** 1.I ends with the merge to `main` and the push; neither has happened. The
  phase branch is pushed and its pull request opened next, so `ci.yml`, `printer.yml` and
  `provenance.yml` run; their results are recorded here before the merge.
- **`phase.json`** was raised on `phase-1` (`340acda`) before the closing real-tier run, not in the
  merge commit as AGENTS.md then said: it is part of the source digest that run records. AGENTS.md
  and the roadmap now describe this practice (D55 j).

No threshold was changed, and no gate was weakened: the closing run needed no fix.

## Fixes made during integration

1. **The printer family never reached `results.json`** (`8df5e73`; the digest it introduced was
   replaced in review round 1 by the import-closure digest of D55 d, see "Review"). The corpus driver and the bench
   computed the summary's `inputsDigest` by two different formulas (the driver hashed
   `path\0bytes\0` plus the `as` line and the options; the bench hashed `path\0bytes` plus a
   pseudo-file `as --version` and `node\00`), so `bench run` judged every summary stale and left out
   the `printer` member. With `landed: 1` the provenance check fails on exactly that ("the printer
   family is absent from the artifact"). The fix then put the one definition in
   `bench/src/printer.ts` (`corpusInputsDigest(repoRoot, asVersion, options)`, over
   `src/foundation/isa`, `src/foundation/asm` and `test/corpus`), had the driver import it, and
   pinned it in `test/unit/bench/printer.test.ts`. The current definition is D55 d:
   `src/shell/toolchain/corpus-inputs.ts`, over the corpus's import closure, pinned by
   `test/unit/shell/toolchain/corpus-inputs.test.ts`; `bench/src/printer.ts` only imports it. No frozen contract changed: the summary is
   still `romlift/corpus-summary@1` and only its digest value moved.
2. **The phase marker** (`340acda`): `test/gates/phase.json` raised to 1 before the final real-tier
   run, because it is part of the source digest.

Nothing else needed a change: the ISA tables, the corpus, the gate bodies and the baselines are as
the waves merged them.

## Known limitations

- **No ROM analysis yet.** romlift itself finds no function until phase 2: the bench rescores the
  PoC's dumps, and `doctor` is the only user command. The rescored table above is the PoC's, the bar
  phase 2 must reproduce (`g2.poc-parity`, `g2.baseline-rows`).
- **`printer.yml`** runs on apt (2.42) and Homebrew (`arm-none-eabi-binutils` 2.47) binutils in CI once
  the phase branch's pull request is open; those two builds are not installed here. Locally the corpus
  passes on two other builds, Arm's 2.45.1 bundle and devkitARM's 2.43.1 ("The corpus").
- **Node 22.18** is not measured locally (the newest 22.x installed is 22.12, below `engines.node`).
  `@match-kit/decomp-yaml` declares `node >=24`, so `npm ci` on Node 22.18 prints an `EBADENGINE`
  warning (a warning only; `engine-strict` stays off). The source digest includes the Node major, so
  the committed artifact (Node 24) is checked by a Node 24 provenance job.
- **agbcc is reported `missing` on this machine.** `doctor` looks on the `PATH` and under
  `./tools/agbcc`; the local builds (`pokeemerald/tools/agbcc`, `agbcc/` under the benchmark root) are
  in neither place. `g1.doctor` allows `missing` because nothing compiles C before phase 4.
- **ARM coverage is partly sampled.** 90 ARM field classes (the rotated immediates, shift amounts,
  12-bit offsets, register lists, branch offsets, `swi`) are covered by the 1,048,576-word sample, not
  exhaustively; `doctor`'s default run uses a 65,536-word sample.
- **Held-out ROMs** are not run in phase 1; their sealed datasets, `g2.held-out` and D53 start in
  phase 2. All three builds reproduce their SHA-1s; docs/benchmark-roms.md already records `tmc`'s
  ELF at `tmc/tmc.elf` and its map at `tmc/build/USA/tmc.map` (since `f4b5c20`), so it needed no
  correction.
- **Owner decisions** (architecture §12) are taken at their documented defaults without waiting;
  none changes phase 1 (`romlift/isa` stays a subpath export, item 6; D40's signatures and D53's
  held-out path start in phases 6 and 2).
